# 潮汕电视直播源

给家里老人用的电视直播源，**潮汕台排最前**，其后是央视和卫视。

本仓库只做一件事：**每天自动重测一遍源，把失效的换掉**。
不含任何 App 源码，播放列表通过 `raw.githubusercontent.com` 供电视盒子拉取。

## 文件

| 文件 | 说明 |
|---|---|
| `builtin_iptv.txt` | 播放列表。既是流水线的**输入骨架**，也是**输出结果** |
| `tools/update_sources.py` | 检测流水线，只用 Python 标准库 |
| `.github/workflows/update-sources.yml` | 每天北京时间 04:10 自动运行 |

## 频道构成

```
潮汕频道（6）  ← 汕头 2 台走 sttv:// 动态签名源（客户端算签名，永不过期）
               + 潮州/揭阳 4 台走官方网页
潮汕广播（2）  ← sttv://
央视频道（18） ← 公开直连 + 央视官方 CDN 后备 + 央视频/央视网页兜底
卫视频道（32） ← 公开直连 + 官方网页兜底
```

## 三类条目的处理方式

| 类型 | 例子 | 处理 |
|---|---|---|
| **公开直连** | `222.169.85.8:9901/tsfile/...` | 会过期（几小时到几天），**每次跑都重新检测换新**，排在第一位 |
| **钉住的官方 CDN** | `*.wscdns.com` | 无 token、不过期，**永不替换**，但排在公开源**之后**当后备 |
| **固定条目** | `sttv://`、`webview://` | 原样保留，排最后 |

### 为什么央视官方 CDN 只当后备

实测央视官方源的 H.264 SPS 里 `pic_order_cnt_type = 3`（规范保留值，合法只有 0/1/2），
Android 9 上的解码器（Media3 与 IJK 都一样）只能解出亮度平面 → **整屏纯绿**。
而同一环境下公开源、河北卫视、浙江卫视 HTTPS、Apple 测试流全部正常。

更麻烦的是**绿屏不触发播放器 `onError`**，App 的多线路自动切换因此失效 ——
若把它排在第一位，一旦复现就是「央视永远绿屏且无人能救」。
故降级为后备：公开源全部失效时才轮到它。

## 怎么用

把下面这个地址填进 App 的 `Constants.BUILTIN_IPTV_UPDATE_URL`：

```
https://raw.githubusercontent.com/a1461750564/chaoshan-tv-sources/main/builtin_iptv.txt
```

App 会自动推导出 9 个加速镜像（6 个前缀代理 + 3 个 jsDelivr 节点）并**并发竞速**，
所以即使 `raw.githubusercontent.com` 在国内直连不通，也能拿到更新。

## 手动跑

```bash
python3 tools/update_sources.py                       # 原地更新
python3 tools/update_sources.py --dry-run             # 只看结果不写文件
python3 tools/update_sources.py -o /tmp/out.txt       # 输出到别处
```

约 2-3 分钟（2000 条候选，40 线程，三级检测）。

## 三级检测

只看 HTTP 200 会得到约 **97% 的假可用率**，所以必须验到分片一级：

1. **连通性** —— 能连上
2. **真 HLS** —— 首行必须是 `#EXTM3U`（排除伪装成 m3u8 的 MP4）
3. **首分片真能拉** —— 且分片数合理（> 300 基本是点播切片，不是直播）
